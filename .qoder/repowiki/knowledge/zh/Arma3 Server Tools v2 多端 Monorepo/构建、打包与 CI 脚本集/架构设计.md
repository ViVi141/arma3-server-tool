脚本按目标产物分层组织，无共享库，每个 .ps1 均为独立可执行入口：
- 桌面端流水线：`build-desktop.ps1` 串联 TypeScript 检查 → `npm test` → `build:service` → `build:web` → `stage-desktop.ps1`（将 `packages/web/dist` 与 `packages/service/dist` 拷贝到 `apps/desktop/electron-resources` 并生成运行时 `package.json` 安装依赖）→ `electron-builder`；`ci-local.ps1` 复用同一序列作为本地预提交校验。
- E2E 环境：`ci-e2e.ps1` 启动 `packages/service/dist/index.js` 为后台 Job，轮询 `/api/v1/health` 后在 `packages/web` 下运行 Playwright chromium 测试，并在 finally 中清理进程。
- Windows 安装包：`build-release.ps1` 通过 `dotnet publish` 产出主程序 + agent/monitoring 宿主 + skills/OpenClaw 脚本，再用 Inno Setup（自动探测或 winget/下载 ISCC）编译 `Arma3ServerTools.iss`，并通过 `_build-metadata.iss` 注入版本/版权信息。
- Android 包：`pack-mobile-apk.ps1` 调用 Vite 构建移动端 web、Capacitor sync、`ensure-mobile-cleartext.ps1` 修改 `AndroidManifest.xml` 与 `network_security_config.xml` 以允许 cleartext HTTP，最后 `gradlew assembleDebug` 输出 `artifacts/mobile/a3st-mobile-debug.apk`。
- 辅助工具：`smoke-desktop-unpacked.ps1` / `zip-desktop-unpacked.ps1` 对已发布目录做冒烟测试与压缩；`test-agent.ps1` / `diagnose-agent.ps1` 针对 Agent Host；`openclaw/a3st-invoke.ps1` 随发布物分发供 OpenClaw skill 调用。
依赖方向单向：脚本 → Node/npm/npx → dotnet/electron-builder/Inno Setup/Gradle，不反向引用源码。
